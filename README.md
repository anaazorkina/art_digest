# Куда пойти на выставку

Персональный арт-редактор: не афиша всего подряд, а короткая подборка выставок,
ради которых стоит выйти из дома. Москва, Петербург, Нижний Новгород, Казань, Челябинск.

**Запуск:** откройте `index.html` двойным кликом. Ничего ставить не нужно —
чистый HTML/CSS/JS, работает офлайн, состояние города запоминается в браузере.

## Структура

| Файл | Что внутри | Кто правит |
|---|---|---|
| `config/institutions.js` | Whitelist институций по городам, веса, квоты, пороги отбора, профиль интересов, ссылка на телеграм-канал | **вы, руками** |
| `data/exhibitions.js` | Временные выставки со всеми сигналами и провенансом | обновляется при рефреше |
| `data/permanent.js` | Постоянные экспозиции музеев | раз в несколько месяцев |
| `assets/app.js` | Движок: score, ярлыки, секции, фильтры | трогать не нужно |
| `assets/app.css` | Оформление | по вкусу |

Всего в whitelist **69 площадок**: 27 в Москве, 18 в Петербурге, 8 в Нижнем Новгороде,
9 в Казани, 7 в Челябинске. Плюс полсотни постоянных экспозиций.

Отдельно закрыты профильные дыры:
* **фотография в Москве** — МАММ, Центр имени братьев Люмьер, Галерея классической
  фотографии (с музеем старинной оптики), Фотоцентр на Гоголевском;
* **архитектура и дизайн в Петербурге** — «Керамарх», Музей Академии Штиглица,
  Музей художественного стекла, Исаакиевский собор, Музей Академии художеств;
* **Челябинск** — краеведческий музей города и есть Исторический музей Южного Урала:
  это один музей, переименованный в 2015 году. Добавлены Музей истории ЮУЖД,
  Музей трудовой и боевой славы и заповедник «Аркаим» (с пометкой, что это 400 км).

### Добавить любимый музей

В `config/institutions.js` найдите нужный город и допишите в `trusted`:

```js
{ id: 'my-gallery', name: 'Моя галерея', site: 'https://example.ru', weight: 2 }
```

`weight` 1–3 — насколько эта площадка сама по себе повышает шансы выставки попасть
в подборку. Убрать музей — удалите объект или поставьте `enabled: false`.
Код при этом менять не нужно.

### Подкрутить строгость отбора

Там же, в `window.SETTINGS`:

* `minScore` — ниже этого выставка вообще не показывается. Подборка размывается? Поднимите.
* `topBlock.minScore` — порог попадания в «Не пропустить». Если никто не дотянул,
  блок просто не показывается — вместо того чтобы заполняться средним.
* `interests` — множители по темам. Любите фотографию — поставьте `photo: 1.15`.

## Как устроен отбор

**Три уровня источников.**

* **A. Trusted** — whitelist из `config/institutions.js`, проверяется всегда.
* **B. Discovery** — всё остальное: галереи, фонды, культурные центры, временные
  пространства. Попадают в подборку только с конкретным сильным проектом
  (`discovery: true` в записи → ярлык «Неочевидная находка»).
* **C. Hype** — арт-медиа, городские медиа, обозреватели, соцсети. Питает поле `hype`.

**Relevance score** считается в `assets/app.js` из сигналов записи (0–3 каждый):
значимость площадки (максимум из сигнала и веса из whitelist), значимость художника
или темы, масштаб, куратор/музей-партнёр, редкость возможности, независимые
упоминания, новизна. Сверху — бонус за хайп и за близость закрытия, затем множитель
из `interests`. Пользователю число не показывается: вместо него editorial label —
**Must see / Хайп / Скоро закроется / Неочевидная находка / Стоит внимания**.

**Ограничение количества.** У каждого города своя `quota` (Москва 12, Челябинск 8).
Если достойных выставок четыре — показываются четыре. Добивать выдачу посредственным
нечем и не нужно.

**Секции на экране.** «Не пропустить» → «Ещё стоит посмотреть» → «Сейчас хайпует» →
«Постоянные экспозиции». Отдельного блока «Скоро закроется» нет: это ярлык на карточке
и фильтр «Скоро закрывается» в строке «Когда» — дублировать выставку ещё одной секцией
незачем.

**Постоянные экспозиции** лежат в `data/permanent.js` и показываются последним блоком:
то, что открыто всегда, и на что часто забывают сходить. У каждой записи есть `star` —
главная вещь, ради которой стоит дойти. При выборе временного фильтра
(«открывается скоро» и т.п.) блок скрывается: к постоянной экспозиции такие фильтры
неприменимы.

**Хайп ≠ реклама музея.** В `hype.reason` пишется, почему именно вокруг проекта шум:
несколько независимых публикаций, рецензии критиков, обсуждаемый художник,
необычная площадка. Собственный промо-поток музея хайпом не считается.

## Даты и достоверность

У каждой записи есть блок `source` с `confidence`.

* `startApprox` / `endApprox` → дата известна приблизительно («ноябрь», «осень»),
  обратный отсчёт до закрытия для такой записи не показывается.
* Записи без дат вообще показываются как обычные, с пометкой «даты уточняются»
  в строке под названием.
* Завершившиеся выставки остаются в базе, но в выдачу не попадают — так видно,
  что они уже проверены, и они не всплывут снова.

Провенанс каждой карточки открывается по ссылке «Откуда данные»: primary source,
дата получения, дата последней проверки, confidence и медиа-упоминания.

**Primary source — всегда официальный сайт площадки** для названия, дат, адреса
и билетов. Медиа используются только для оценки значимости и хайпа. Если одна
выставка встретилась на сайте музея, в афише и в трёх статьях — это одна запись,
у которой медиа лежат в массиве `media`.

## Регламент обновления

| Что | Как часто | Что делаем |
|---|---|---|
| Полный кураторский дайджест | раз в месяц | заново обходим whitelist + discovery, пересобираем `EXHIBITIONS` |
| Блок «Хайп» | раз в неделю | пересматриваем поля `hype`, buzz протухает быстрее месячного цикла |
| Сверка дат | чаще всего остального | проверяем `end` у текущих записей, чтобы не показывать завершённое |

Даты последних проверок лежат в `window.DIGEST_META` в начале `data/exhibitions.js`
и выводятся в подвале приложения.

### Что происходит само, без вас

**Завершившиеся выставки исчезают сами.** Статус считается в браузере от текущей даты,
поэтому приложение никогда не покажет закрывшуюся выставку как идущую и не соврёт
про «осталось 3 дня». Устаревшие данные не врут — они **пустеют**: выставки кончаются,
новые никто не добавил, и город постепенно схлопывается.

**Сайт сам сознаётся, что устарел.** Если дайджест не обновлялся дольше
`SETTINGS.staleAfterDays` (по умолчанию 45 дней), в подвале появляется оранжевое
предупреждение.

**Раз в месяц приходит напоминание.** `.github/workflows/monthly-check.yml` первого
числа запускает `scripts/check-data.mjs` и заводит Issue с готовым списком дел:

* сводка по городам — где стало пусто или мало;
* что уже закрылось и подлежит удалению;
* что закроется в ближайший месяц — проверить, не продлили ли;
* записи без дат и с `confidence: low`;
* битые ссылки (проверяются HTTP-запросом);
* готовый промпт, который остаётся скопировать в Claude Code.

Workflow можно запустить руками в любой момент: вкладка **Actions → Ежемесячная
проверка данных → Run workflow**. Локально — `node scripts/check-data.mjs --no-net`
(флаг пропускает проверку ссылок, работает мгновенно).

⚠️ GitHub отключает запланированные workflow в репозиториях, где 60 дней не было
активности. Если вы месяцами ничего не коммитите, придёт письмо с предложением
включить обратно — одна кнопка.

### Как выложить обновление на GitHub

Локальная папка не связана с репозиторием, git не установлен — значит файлы
заливались через веб-интерфейс. Порядок тот же:

1. На странице репозитория **Add file → Upload files**.
2. Перетащить изменённые файлы, сохранив пути (`data/exhibitions.js` — в папку `data`).
3. **Commit changes**. GitHub Pages пересоберёт сайт за минуту-другую.

Файлы `.github/workflows/monthly-check.yml` и `scripts/check-data.mjs` нужно залить
один раз — после этого проверка заработает сама.

### Промпт для месячного рефреша

> Обнови `data/exhibitions.js`. Пройди по whitelist из `config/institutions.js` для
> всех пяти городов, проверь текущие и ближайшие временные выставки. Отдельно поищи
> значимые проекты вне whitelist (`discovery: true`) и свежий buzz за последние 30 дней
> для поля `hype`. Только художественные и культурные выставки: живопись, графика,
> скульптура, фотография, архитектура, дизайн, современное искусство, медиа-арт,
> историко-художественные проекты. Без мастер-классов, лекций, концертов, экскурсий
> и постоянных экспозиций без отдельного инфоповода. Для каждой записи primary source —
> официальный сайт площадки; если даты не подтверждаются, ставь `datesConfirmed: false`.
> Обнови `DIGEST_META`.

### Промпт для недельного рефреша хайпа

> Проверь только поля `hype` в `data/exhibitions.js` для города X: какие выставки
> сейчас реально обсуждают в арт-медиа, городских медиа и у обозревателей за последние
> 30 дней. Собственную рекламу музея хайпом не считай. Обнови `DIGEST_META.hypeChecked`.

Стартовый набор собран из открытых источников **30.08.2026**: 30+ актуальных выставок
по пяти городам. Сайты музеев отдают контент через JavaScript и на прямую загрузку не
отвечают, поэтому часть дат взята из медиа и афиш — у таких записей стоит

Точные даты (`confidence: high`) есть там, где их публиковали явно: «Хлеб» в «Зотове»,

при ближайшем рефреше — промпты выше.

## Дизайн

iOS: системная типографика (SF Pro / Segoe UI Variable), segmented control для городов,
капсульные фильтры, карточки со скруглением 20 px и мягкой тенью, системная палитра
(`#007AFF`, `#FF3B30`, `#FF9500`, `#34C759`, `#FF2D55`). Тёмная тема подхватывается
автоматически из настроек системы через `prefers-color-scheme`.

Обложки карточек — градиент плюс геометрический SVG-паттерн, свой на каждую тему:
аркада для классики, круги для современного искусства, диафрагма для фотографии,
изометрическая сетка для архитектуры, ромбовидный орнамент для истории. Паттерны
встроены в CSS как data-URI, внешних картинок нет — приложение полностью работает офлайн.

**Мобильные:** одна колонка, `viewport-fit=cover` и `env(safe-area-inset-*)` для
экранов с вырезом, города и фильтры прокручиваются горизонтально до самого края,
тач-таргеты не меньше 44 px, подвал перестраивается в две строки,
`prefers-reduced-motion` отключает анимации.

## Телеграм-канал

Ссылка на канал живёт в `window.TELEGRAM` в конце `config/institutions.js` — там же
меняются заголовок, подпись и текст кнопки. Баннер выводится в подвале.
